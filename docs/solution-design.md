## 1. Project Purpose

### What It Does

Systematic Dev Kit is a Claude Code plugin that provides opinionated, reusable skills for building production-ready full-stack applications. It guides developers through structured, step-by-step workflows covering project scaffolding, feature planning, codebase exploration, brand identity design, and automated documentation maintenance. Each skill is an agent-driven capability invoked via a `/systematic-dev-kit:<skill-name>` slash command inside the Claude Code IDE.

### Who It's For

Developers using Claude Code (Anthropic's official CLI/IDE plugin) who want to accelerate full-stack development with systematic, best-practice workflows rather than ad-hoc generation.

### Problem It Solves

Without this plugin, developers must hand-craft project structures, manually plan feature layers, and keep architecture docs in sync by hand — all of which are error-prone and time-consuming. Systematic Dev Kit eliminates that friction by encoding opinionated workflows as executable skills that interact with the filesystem and git on the developer's behalf.

### Non-Goals

- Not a deployable web application — it generates projects but is not itself a running service.
- Does not provide runtime monitoring, logging infrastructure, or CI/CD pipelines for generated projects.
- Does not manage dependencies or package registries; generated projects require the developer to run `npm install` and `docker-compose up` manually.

## 2. Solution Architecture

### System Overview

Systematic Dev Kit is a Claude Code plugin distribution package — a collection of Markdown-based skill definitions that Claude's agent runtime reads and executes. When a developer invokes a skill, the Claude Code harness reads the relevant `SKILL.md`, instantiates an agent, and the agent interacts with the local filesystem, git, and optionally spawns sub-agents for focused sub-tasks. The plugin has zero runtime dependencies of its own; all generated artifacts (projects, docs, brand files) live in the developer's working directory. Skills are composable: the `plan` skill invokes `explore`, and `doc-maintainer` spawns `explore` sub-agents for codebase archaeology.

### Data Flow

1. **Project scaffolding**: Developer invokes `/systematic-dev-kit:init` → agent asks 5 questions → clones `dev-kit-scaffolding` template repo → removes unwanted components → replaces `{{PROJECT_NAME}}` placeholders → optionally initialises git and installs npm dependencies → ready-to-run monorepo delivered.

2. **Feature planning**: Developer invokes `/systematic-dev-kit:plan` → agent gathers feature intent → optionally invokes `explore` to scan existing code → asks layer-by-layer design questions (adaptive depth) → surfaces tradeoffs → writes `specs/<feature>.md` after approval.

3. **Documentation init**: Developer invokes `/systematic-dev-kit:doc-maintainer init` → agent checks out `chore/claude-maintain` branch → spawns whole-system Explore sub-agent → discovers and classifies domains → spawns per-domain Explore sub-agents → writes `docs/solution-design.md` + `docs/<domain>/overview.md` → commits and pushes → restores original branch.

4. **Daily doc maintenance**: Cron triggers `maintain.sh` → invokes `doc-maintainer maintain` → detects stale or new domains → spawns targeted Explore sub-agents → patches affected docs → commits → no-op exit if nothing is stale.

5. **Brand design**: Developer invokes `/systematic-dev-kit:brand-designer` → six-phase emotional discovery conversation → synthesises Creative Direction Brief → generates `brand/` directory (guideline, CSS theme, optional Tailwind config, showcase HTML, optional effects CSS) → validates output.

### Infrastructure & Deployment

This plugin is distributed as a Git repository cloned locally and loaded with `claude --plugin-dir /path/to/systematic-dev-kit`. There is no server, container, or cloud deployment for the plugin itself. Generated full-stack projects are independently deployable via Docker Compose (`docker-compose up`) on the developer's machine.

## 4. Key Architectural Decisions

- **Skill-as-Markdown**: All skill logic lives in `SKILL.md` files with YAML frontmatter, not in code. This makes skills human-readable, diff-friendly, and model-agnostic — any Claude model can execute them without compilation or deployment.

- **Opt-out scaffolding over opt-in**: The `init` skill presents the full stack by default and asks users what to *remove*, reducing cognitive load and keeping the happy path (full-stack) near-zero friction.

- **Template-clone over direct generation**: `init` clones a pre-built template repo rather than generating files from scratch. This is faster, lower-token, and keeps the generated project structure in sync with upstream template improvements.

- **Tiered codebase investigation**: The `explore` skill reads documentation before code (Tier 1), then structure files (Tier 2), then targeted source (Tier 3), with a sufficiency gate at each tier. This keeps investigation token-efficient and avoids reading irrelevant code.

- **Dedicated docs branch**: `doc-maintainer` always operates on `chore/claude-maintain`, never on `main` or feature branches. This prevents auto-generated commits from polluting the source history.

- **Approval gates before file generation**: Both `plan` and `brand-designer` require explicit user sign-off on synthesised briefs/specs before writing any files. This ensures generated artifacts reflect actual intent rather than misinterpreted questions.

- **Per-domain staleness tracking via frontmatter**: Each `overview.md` carries a `last_updated` date in its YAML frontmatter. The `find-stale-domains.sh` script reads this field to determine which domains need refreshing, enabling targeted incremental updates rather than full rebuilds.
