# Bootstrap New Project (Deprecated)

## What Is Bootstrap New Project?

Bootstrap New Project is a deprecated project scaffolding skill that generated complete full-stack application structures by writing files directly from templates. The primary object it owned is a **NewProject** — a runnable monorepo with Clean Architecture backend (Express + TypeScript + CQRS), atomic-design frontend (React + Vite + MUI), and Docker Compose orchestration. It has been superseded by the `init` skill, which clones a pre-built template repository instead of generating files from scratch, making it faster and lower-token.

## How It Works

A NewProject was created through a five-phase interactive workflow. The developer answered questions about project name, target directory, git initialisation preference, and whether to install dependencies immediately. The skill then validated that Docker was installed (a hard requirement), generated the complete directory tree across backend and database domains, wrote all configuration files (`docker-compose.yml`, `tsconfig.json`, `package.json`, `openapi.yaml`, `vite.config.ts`), and created placeholder `database/` and `agent/` directories for future implementation. Optionally, it ran `git init` and `npm install` in both backend and frontend workspaces. The developer received service URLs: frontend at `:3000`, API at `:4000`, API docs at `:4000/api-docs`.

## Code Map — Which Code Touches This

- **Models / Schema**: `skills/bootstrap-new-project/SKILL.md` — defines all generated file contents inline, including TypeScript configs, package.json dependency lists, docker-compose structure, and OpenAPI spec skeleton.
- **Business Logic / Services**: `skills/bootstrap-new-project/SKILL.md` — five-phase workflow: Prompt → Validate → Generate → Configure → Establish; Docker presence check; SSH/HTTPS clone fallback is not applicable here (files are generated, not cloned).
- **API / Interface**: Invoked as `/systematic-dev-kit:bootstrap-new-project`; interactive prompts for project metadata.
- **Persistence**: Writes all files directly to the target directory; no template repository dependency.
- **External callers**: Superseded by `systematic-dev-kit:init`; no other skills call into this domain.

## Internal Architecture

**Clean Architecture Layers (generated backend)**: Domain (entities, repository interfaces) → Usecases (CQRS command/query handlers) → Interface (HTTP controllers, DTOs, route definitions) → Infrastructure (database connections, ORM repositories). This layering is generated as an empty scaffold for developers to populate.

**Atomic Design (generated frontend)**: Components decomposed into five levels (atoms → molecules → organisms → templates → pages) to enforce reusability.

## Dependencies

- **Internal**: None — standalone skill, no inter-skill dependencies.
- **External**: Docker (hard requirement, checked at validation); npm (dependency installation); packages written into generated `package.json` include Express, cors, dotenv, swagger-ui-express, zod, React, react-router-dom, MUI, Vite, TypeScript.

## Gotchas

- **This skill is deprecated.** All new project creation should use `/systematic-dev-kit:init` instead, which clones a maintained template repo rather than regenerating files from inline templates.
- Docker is a hard prerequisite — if not installed, the skill halts with no graceful fallback.
- The `database/` and `agent/` directories are empty placeholders. They require full manual implementation post-scaffold; the skill provides no starting schema or agent boilerplate.
- The generated `openapi.yaml` is a minimal skeleton. Developers must expand it to reflect actual API contracts; no endpoints are generated by default.
- No authentication middleware is generated. Adding auth requires manual implementation.
