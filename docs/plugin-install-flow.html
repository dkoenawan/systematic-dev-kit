compass-labs · plugin lifecycle

Install & Update Flow

How the plugin reaches a developer machine — and how it stays current
1
New VM — Fresh Install
One-time setup on a brand-new machine. Goal: every skill auto-loads on every claude session with no per-project flags.
1
user Clone the repository
Pick a permanent home — this directory is the live source of truth. git clone https://github.com/dkoenawan/compass-labs.git ~/dev/compass-labs
The path you clone to is registered as the local marketplace. Move it later and you must re-run step 2.
2
system Register as a local marketplace
Tells Claude Code where to resolve compass-labs plugin names. claude plugin marketplace add ~/dev/compass-labs Writes into ~/.claude/settings.json → extraKnownMarketplaces.
3
system Install the plugin
Snapshots the current working tree into the plugin cache. claude plugin install compass-labs@compass-labs Creates a versioned copy at:
~/.claude/plugins/cache/compass-labs/compass-labs/<version>/
Important: Claude loads from the cache, not the working directory. Changes to the repo do not take effect until you run claude plugin update.
4
verify Confirm it loaded
claude plugin list # compass-labs@compass-labs Status: ✔ enabled Then open a new Claude session and test a skill: /compass:explore
!
known gap No install script exists today
The four steps above are manual. A single scripts/install.sh should wrap them — idempotent, safe to re-run. # scripts/install.sh (to be built) check if marketplace already registered → skip if yes claude plugin marketplace add "$(pwd)" claude plugin install compass-labs@compass-labs claude plugin list | grep compass-labs
✓
done Skills available in every session
No --plugin-dir flag needed. To update later, see section 2 below.
Session-only mode (no install): Run claude --plugin-dir /path/to/compass-labs. Nothing is written. Skills vanish when the session ends.
2
Releasing an Update
How a change in the working directory becomes active. The cache is what Claude reads — it must be refreshed explicitly. A restart is required to load the new cache.
Working directory
~/dev/compass-labs/
Your editable source. Git-tracked.
Plugin cache (what Claude reads)
~/.claude/plugins/cache/.../<version>/
Snapshot from install time.
Stale gap
Cache ≠ working dir after any edit. No warning. You silently run old skills.
1
user Edit skill files in the working directory
Modify skills/*/SKILL.md, add a new skill directory, or fix hooks. Changes are not live yet — Claude still runs the cached version.
2
user Bump version in plugin.json
Follows semver. The version string is the cache key — if it doesn't change, the old snapshot is reused. # .claude-plugin/plugin.json "version": "0.5.1" ← patch: bug fix / doc tweak "version": "0.6.0" ← minor: new skill added "version": "1.0.0" ← major: breaking interface change
Known gap: Nothing enforces this. A post-commit hook should warn when skill files changed but version is unchanged.
3
user Commit and tag the release
git add .claude-plugin/plugin.json git commit -m "chore: bump to v0.6.0" claude plugin tag # validates + creates git tag git push origin main --tags claude plugin tag validates that plugin.json version and marketplace entry agree, then creates a compass-labs--v0.6.0 tag.
4
system Refresh the local cache
Re-snapshots from the working directory into a new versioned cache folder. claude plugin update compass-labs@compass-labs
For other developers: they git pull the repo then run the same claude plugin update command.
5
system Restart Claude
The running process holds the old cache in memory. A full restart is required. claude plugin list # Version: 0.6.0 Status: ✔ enabled
!
known gap No release script exists today
Steps 2–4 are manual and easily forgotten. A scripts/release.sh should automate the sequence. # scripts/release.sh patch|minor|major (to be built) read current version from plugin.json compute next version (semver bump) update plugin.json git add + commit "chore: bump to vX.Y.Z" claude plugin tag git push origin main --tags claude plugin update compass-labs@compass-labs echo "Restart Claude to activate vX.Y.Z"
Stale cache is silent. If you skip the version bump, claude plugin update overwrites the same version folder — but the running session won't pick it up until you restart. Always restart after any update.
3
Backwards Compatibility
What kinds of changes break existing users. Because skills are loaded by name, renames and removed skills are the main breakage vectors.
Change type Semver Impact Safe migration path
Improve skill instructions / prose patch None — same invocation, better output Just ship it.
Add a new skill minor None — additive only Just ship it. New slash command appears.
Add optional flag / phase to existing skill minor None — existing invocation unchanged Just ship it. Default behaviour must be preserved.
Rename a skill major Breaking. Old slash command stops working. Keep old skill as a redirect stub for one major version before removing.
Remove a skill major Breaking. "Skill not found" error for existing users. Deprecation stub for one major version. Note in changelog.
Change output file path convention minor/major Cron jobs and scripts referencing old paths break. Detect old path and migrate in the skill, or note in release docs.
Change cron script signature major Existing cron jobs with old args may fail silently. Version the script (e.g. install-schedule-v2.sh) or add a migration notice.
Update hooks in hooks.json minor Hook runs on user machine — unexpected side effects possible. Announce in changelog. Keep hooks non-destructive and idempotent.
Rename plugin.json fields major CLI may fail to parse the manifest. Follow the official plugin schema. Validate with claude plugin validate .
Deprecation lifecycle
1
deprecate Mark skill as deprecated in SKILL.md
--- name: old-skill-name description: "[DEPRECATED — use /compass:new-name] ..." --- > **Deprecated.** Removed in next major version. > Use `/compass:new-name` instead.
2
deprecate Ship the deprecation as a minor release
Both old and new skill exist simultaneously. Users migrate at their own pace. The deprecated description surfaces in claude plugin details.
3
remove Remove in the next major release
Delete the directory, bump to the next major, document in the changelog.
The bootstrap-new-project skill is currently in this state — deprecated in favour of init, but the directory still exists. Should be removed in v1.0.0.
Rule of thumb: Same slash command, same result or better → minor/patch. Same slash command, different result or error → major.
4
Version Lock
Mechanisms to pin a specific version — for reproducibility, CI environments, or staying on a known-good release while upstream moves forward.
Current limitation: The directory marketplace has no native version pin — claude plugin update always installs from the current working directory. To lock, control what the working directory contains via git.
Strategies
Git tag checkout
Check out a release tag. The snapshot taken by plugin install corresponds to that exact release.
cd ~/dev/compass-labs git fetch --tags git checkout compass-labs--v0.5.0 claude plugin update compass-labs@compass-labs
Git commit SHA pin
Exact reproducibility. Pin to a specific commit rather than a tag. Useful in CI or shared team environments.
git checkout 5b61555 claude plugin update compass-labs@compass-labs
Separate clone per version
Keep multiple clones at different versions registered as separate marketplaces. Allows side-by-side testing.
git clone ... ~/dev/sdk-stable # v0.5.0 git clone ... ~/dev/sdk-next # main claude plugin marketplace add ~/dev/sdk-stable claude plugin marketplace add ~/dev/sdk-next
Disable auto-update
Don't run claude plugin update. The installed cache stays frozen at the version you last installed.
# confirm currently locked version claude plugin list # Version: 0.5.0 ← stays here

state Installed at v0.5.0 — locked
Working directory may be ahead of cache. Claude runs v0.5.0 from cache. No change until you explicitly act.
?
Decision — do you want to update?
Yes — update to latest git pull && claude plugin update
Moves to whatever version is in plugin.json. Restart required.
No — stay locked Do nothing. Cache stays at v0.5.0 indefinitely.
Pin to specific tag git checkout v0.5.1 && claude plugin update
Update to a chosen release, not latest.
